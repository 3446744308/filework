# ADR-013: 公告样式模型（白名单枚举 + 空值即默认主题）

> Status: Accepted | Date: 2026-10-12 | Deciders: zwh | 关联 RFC: RFC-004 §4 | 影响：`server/notice.js`、`web/src/components/NoticeBar.jsx`、`web/src/pages/Upload.jsx`、`web/src/pages/Admin.jsx`、`web/src/utils.js`、`web/src/App.jsx`、`web/src/index.css`

## Context

公告原来是「弹窗 / 顶部条 / 两者」三选一的单一形态，位置固定在页头下方、底色与字色写死在 CSS，滚动只有「超宽时右→左跑马灯」。运营侧的诉求（自定义字体颜色与背景颜色、不同位置、多种滚动）需要扩展数据模型与渲染方式，于是要定几个口径：

- 位置与滚动是**枚举**还是自由定位（如 `top: 12px`）？
- 颜色是否允许任意 CSS 值（`rgb()`/渐变/关键字）？
- 配色作用范围：只作用于公告条，还是弹窗也套用？
- 新字段如何与既有 `notice.json` 兼容？
- 悬浮条与弹窗的层级关系？

## Decision

1. **位置与滚动用白名单枚举**：`position ∈ {top, bottom, fixed-top, fixed-bottom}`、`scroll ∈ {none, left, right, up, bounce}`；非法值静默回落默认（`top` / `left`）。理由是这两种配置的每一种取值都对应一段确定的 CSS 与测量逻辑，枚举让「客户端与服务端对同一份配置的行为完全一致」，也避免运营配出无法维护的自由定位。
2. **颜色只接受十六进制**（`#RGB`/`#RRGGBB`，带不带 `#` 均可），三位补全为六位并统一小写；其余一律存空字符串。空字符串的语义是**「跟随默认主题」**，不是一个颜色值——因此前端把空值翻译成「不设置内联样式」，主题升级/换肤时未配色的公告自动跟随。
3. **配色同时作用于公告条与弹窗**（内容块级别）：`utils.noticeColors()` 是一处实现，公告条的内联样式与弹窗内容块共用。弹窗的边框、标题栏仍由 antd 控制，避免整窗反色带来的可读性风险。
4. **同一份 `normalize()` 用于读与写**：`getNotice()` 对磁盘内容归一化、`saveNotice()` 再盖 `updatedAt`。好处是旧文件（缺字段）与手工改坏的字段都不会让接口返回不可用数据，也**不需要迁移脚本**；代价是每次读取都要过一遍白名单（O(1)，可忽略）。
5. **单组件 + 双槽位**：`App.jsx` 渲染上/下两个 `NoticeBar`，组件按 `position` 归属槽位（`top`/`fixed-top` → 上槽，`bottom`/`fixed-bottom` → 下槽），共享模块级 `noticePromise` 只抓一次公告。相比「组件自行决定插到哪」，槽位方案让流内位置（顶部/底部）的 DOM 位置正确，而悬浮位置不受槽位影响。
6. **悬浮条层级低于弹窗**：`z-index: 900`（antd Modal 为 1000）。公告条是常驻信息条，弹窗是需要用户确认的模态内容；两者同时出现时弹窗必须可操作。
7. **横向行为由 `scrollFill` 开关决定（默认关闭 = 仅超出才滚），纵向溢出才滚**（2026-10-12 两次修订，见下方「修订记录」）：
   - 横向 `left`/`right`，`scrollFill = false`（默认，也是 RFC-004 首批行为）：只有内容真超出可视宽度（`scrollWidth > clientWidth`）才滚动，两份副本 `translateX(0 ↔ -50%)`；装得下则静态显示（单行省略号 + 悬停看全文）。适合「免责声明 / 短文提示」这类不该动的公告。
   - 横向 `left`/`right`，`scrollFill = true`：**无论内容宽窄都滚动**——内容装得下时按 `ceil(视口宽 / (内容宽 + 间距))` 重复内容填满整条，总副本 `2 × 每半份`，位移仍为 `translateX(0 ↔ -50%)`（半轨道 ≥ 视口宽 ⇒ 不露白、无缝）。适合「活动轮播 / 小字告示」这类希望一直动的公告。
   - 两种模式都真实存在需求（“跑马灯要一直在动” vs “短文安静显示”），因此不做成全局常量，也不在两种行为里二选一，而是一个开关字段（该开关只在横向模式下有意义；`none` 下无效，纵向模式下无效）。
   - 纵向 `up`/`bounce`：仍比较 `scrollHeight > clientHeight`（内容先按容器宽度换行）；**内容不足 2 行时不滚**——单行内容纵向位移没有可见运动，只会留下空白，因此「不滚 + 管理端提示『纵向需 ≥2 行内容』」。纵向模式强制 `pre-wrap + word-break`，否则单行超长文本会横向被裁切而纵向动画毫无意义。
   - `none`：永不滚动（单行省略号）。
8. **本期只做背景色与文字色**：字号、圆角、透明度、字体族等留待真正被提出时再加（每加一项都要在管理端、校验、测试三处同步，边际收益递减）。

## Alternatives（决策 7 两次修订时反复评估）

- **只保留单一横向行为**（要么一律滚、要么只溢出才滚）：实现最简单，但两种行为都有真实场景（活动轮播要一直动、免责声明要安静），单一切法总有一边不满足。**已采纳为开关**（见修订记录二），不再否决。
- **一律滚动但缩短循环（按内容宽而非视口宽做位移）**：短内容会在宽屏上出现大片空白再回卷，视觉上是「闪烁的空条」。否决（开启填满时改为填满整条 + 半轨道位移）。
- **纵向也一律滚动**：单行内容纵向位移无可见运动（两份相同副本互换），等于骗人。否决。
- **把开关做成全局设置（对所有公告生效）**：公告是逐条的：同站点里维护通知希望安静、活动告示希望滚动，全局开关会在切换公告时来回改。否决（做成公告自身字段，随预设一起保存）。

- **自由定位（`top: 12px; left: 8%` 等）**：表达力最强，但要处理碰撞、移动端换算与「配歪了」的举证责任；运营真实诉求只是「顶部/底部/悬浮」。否决。
- **任意 CSS 颜色值（含 `rgb()`/渐变/`transparent`）**：服务端校验退化为「几乎不校验」，前端还要处理渐变色下的字色对比度；十六进制已覆盖取色器能表达的全部纯色。否决。
- **只作用于公告条（弹窗保持默认）**：同一份公告在两种展示形态下配色不一致，运营会认为是 bug。否决（改为同时作用于内容块）。
- **把配色写进 CSS 变量注入 `<style>`**：能复用主题类名，但引入运行时样式注入与清理问题，且内联样式已足够（只有几个键）。否决。
- **多公告模型（数组 + 优先级 + 时间窗）**：需求未提，提前设计会让「单例 JSON + 一个 GET」变成调度问题。否决，列 backlog。

## Consequences

- 正：新增样式**零迁移**（旧文件自动补齐）；一份配置在服务端与浏览器之间语义一致（白名单 + 归一化）；公告条与弹窗共用一个取色口径；悬浮条不影响页面布局，也不遮挡弹窗。
- 正：纵向滚动对多行长公告可用（换行后按高度滚动），横向滚动保持原有的「无缝 + 悬停暂停」体验。
- 负：`z-index: 900` 是硬编码约定，若未来在页面上引入其他固定浮层需重新协调层级。
- 负（决策 7 修订带来）：短公告在宽屏上会同时出现多份相同文本（自动填满的必然结果）；长公告的循环周期会随半轨道宽而变长（速度恒为 60px/s，最长一屏可达数十秒）。
- 负：枚举限制了运营表达力（例如「左上角贴边」「斜向滚动」都不支持）；如需更多形态，应扩枚举并同步 CSS、管理端与用例，而不是放开为自由值。
- 负：颜色只做纯色，渐变/图片背景不支持。
- 负：未处理 `prefers-reduced-motion`，对动效敏感的用户只能关闭公告条（列 backlog B5-1）。

## 修订记录

- 2026-10-12 修订一（决策 7）：横向由「溢出才滚」改为「一律滚动（不足自动填满）」，以解决「选了滚动方式看不到动」的真实反馈；纵向维持溢出才滚并提示「需 ≥2 行」。对应 RFC-004 增量二。
- 2026-10-12 修订三（backlog B5-1 关闭，动效无障碍）：`NoticeBar.jsx` 新增 `useReducedMotion()`（`window.matchMedia('(prefers-reduced-motion: reduce)')` + `change` 监听，`preview` 预览同样生效），测量时**优先于滚动分支**降级为静态（`scrolling: false` + 文案「系统已开启「减少动态效果」，降级为静态展示（悬停可见完整内容）」），静态仍保留单行省略与 `title` 完整提示；视图加 `role="status"` + `aria-live="polite"`（复制副本保持 `aria-hidden`，读屏不会重复播报）；`index.css` 加 `@media (prefers-reduced-motion: reduce)` 关掉跑马灯动画并收回宽度作为 CSS 层兜底。验证：`scripts/e2e-browser.js` E2E-9 用 `Emulation.setEmulatedMedia` 模拟真实偏好（无动画、不复制、省略与语义保留），清除模拟后断言动画恢复。
- 2026-10-12 修订二（决策 7，最终形态）：运营指出两种行为都要保留（并举例「内容没超出可视宽度就不该触发滚动」），因此改为新增公告字段 `scrollFill`（默认 `false` = 仅超出才滚，即首批行为；`true` = 一律滚动并自动填满），管理端加一个开关；预设因为存整条公告快照，这个字段自然随预设一起保存/启用。对应 RFC-004 增量三、DEVELOPMENT §5/§8、`scripts/e2e-browser.js` E2E-9（两种模式各跑一次）/E2E-10（开关可开可关 + 预设摘要标注）。
