# ADR-005: 单元级编码择优（raw/gzip/brotli）与单元级去重

> Status: Accepted | Date: 2026-10-12 | Deciders: zwh | 关联 RFC: RFC-002 §4.2/§4.3 | 影响：`server/codec.js`、`server/compress.js`

## Context

RFC-001 的容器只用 gzip，且没有跨块去重：

- **单编解码**：文本类数据上 brotli 明显优于 gzip（节点 zlib 内置 brotli，仍为零依赖），不用就是白扔体积；但对已压缩内容两者都无收益，必须允许"不压"。
- **无去重**：同一段内容（重复日志、稀疏区、模板化行）在文件里出现 N 次就要存 N 份，也要传 N 份。
- **传输现实**：明文 HTTP 下"浏览器必定声明 br"不能假设（现代 Chrome 安全上下文会声明 `br`，但代理/旧客户端可能只声明 `gzip`），所以存储态最好别只押注 brotli。

## Decision

1. **逐单元多编解码择取最小**（`codec.encodeUnit`）：候选 `raw` / `gzip(level 6)` / `brotli(quality 5)`，取最小者；**永不写入比原始更大的数据**（无收益即存 `raw`）。
2. **brotli 边际规则**：只有当 `br.length < gzip.length × 0.96`（小 4% 以上）时才采用 brotli，否则保留 gzip。原因：gzip 是"明文 HTTP 也能 0 拷贝直传"的编码（`Accept-Encoding` 必含 gzip），押注 brotli 会让部分客户端走"解 br 再压 gzip"的重编码路径。
3. **候选可配置**：`COMPRESS_CODECS=br,gzip`（默认）；设为 `gzip` 可省掉一半压缩 CPU（代价是体积略大）。
4. **单元级去重**（`compress.packUnits`）：对每个单元算 `SHA-256` 截 128bit 作为内容哈希，命中已存单元时该单元只记录 `{ o, c, r, z, d }`——`o/c/r/z` 与源单元完全一致、`d` 指向源单元下标，**不新增任何存储字节，也不重复传输**（源载荷本身就是可直接解码的单元）。
5. **去重只在单个文件内**：哈希表为打包时的内存 `Map`，不落盘、不跨文件、不跨请求；不引入全局内容索引与引用计数（那会带来删除时序与磁盘回收的一整套复杂度）。

## Alternatives

- **只用 gzip（RFC-001 现状）**：实现最简，但白扔 5%~14% 体积（实测：源码语料 gzip-6 18.7% vs brotli-5 16.1%）。否决。
- **只用 brotli（含质量 11）**：比例最好，但①明文 HTTP 下多数客户端声明 `br` 不可假定；②质量 11 在 300MB 上传上耗时不可接受（实测 8MB 语料 br-9 需 278ms，已 5 倍于 br-5）。否决。
- **引入 zstd / 外部压缩库**：Node 无内置 zstd（`zlib.zstd*` 依赖较新版本），违反"优先零依赖"约定（RFC-001 §7 已否决同类）。否决。
- **跨文件全局去重**：需要全局块索引与引用计数，删除文件时要判断块是否仍被引用，且会把"文件"与"存储块"解耦成两套生命周期。收益（同站点重复文件少）与风险不成比例。否决（RFC-002 §7 列为非目标）。
- **固定字典 / 预训练字典（brotli 自定义字典）**：能再压 10% 左右，但字典需随包分发并绑定内容类型，构建与维护成本高。列为后续话题。

## Consequences

- 正：可压缩文本的存储与传输体积取"当前实现能达到的最小"，且**永不膨胀**；brotli 占优的场景（多数文本）在存储上直接受益，传输上按协商走直传或重编码。
- 正：去重对"重复块/稀疏区"是数量级收益（测试：700KB 全零文件去重后 `storedSize` 仅几 KB，且去重单元与源单元共用载荷，下载逐字节一致）。
- 负：压缩是"双编码实测"，比单 gzip 多一次 CPU 开销（约 +30%~60% 压缩耗时，实测 br-5 与 gzip-6 速率相当，整体接近一倍）；对上传延迟有影响，故提供 `COMPRESS_CODECS=gzip` 的降级开关。
- 负：单元表新增 `z`/`d` 字段（旧代码不认识的字段），旧容器 `gzip-blocks` 只读兼容、新容器不被旧版本识别——已在 RFC-002 §4.1 明确"升级是单向门"，回滚需保留旧构建。
- 风险：去重哈希截断到 128bit，命中错误即数据错误；以 256 单元以内的规模，碰撞概率可忽略（远低于磁盘静默损坏率），且去重命中会复核 `r`（原始长度）一致后才会引用。
